# 账号中心（登录/注册）

个人插件（非官方）。提供**可交互且可用的登录/注册界面**，运行在插件详情页的隔离 iframe 沙箱中，通过受控桥接调用账号接口实现真实登录。

## 使用方式

1. 在「插件 → 我的」中导入本目录（`G:\新建文件夹 (8)`）。
2. 打开插件详情页，点右上角「打开界面」，即可看到登录/注册表单。
3. 注册：填昵称 + 密码（6-64 位）+ 确认密码 + 同意协议 → 提交后系统按注册顺序分配账号（`user_000001` 形式）并显示。
4. 登录：填账号 + 密码 → 成功后显示已登录状态，登录态保存在插件内 localStorage（沙箱独立存储）。
5. 邮箱字段暂不启用（灰显 + 禁止光标）。

## 工作原理（受控桥接）

- 沙箱 iframe（opaque origin，无 `allow-same-origin`）无法直接访问主应用接口。
- 界面通过 `parent.postMessage` 发出受控请求（`{__pluginBridge:'request', id, path, body}`）。
- 主应用父窗口校验消息来源必须是当前 iframe，注入该插件的 `pluginKey`，调用 `/api/plugin-bridge/call`。
- 后端桥接层从远程白名单（`ekstai/uiw/plugin-acl.json`，token 仅服务端持有）校验：
  - 该 pluginKey 是否被授权
  - 该接口路径是否在允许列表（精确匹配，仅 `/api/auth/register`、`/api/auth/login`）
- 校验通过后代理调用账户服务（Neon PostgreSQL），结果回传 iframe。
- **任何不在白名单的插件或接口一律拒绝**（fail-closed；远程不可达时用上次缓存，无缓存则全拒）。

## 安全边界

- 接口白名单由远程仓库集中控制，可随时远程调整，无需改客户端。
- 插件无法伪造 pluginKey（由父窗口注入）；无法调用白名单外接口；无法访问主应用 DOM/cookie。
- 账号数据存 Neon，密码 bcrypt 哈希，输入参数化查询防注入。

## 账号体系设计

- 账号：`user_000001`（按注册顺序），登录用「账号 + 密码」。
- 用户 ID：库中 UUID，可作全软件统一 ID。
- 输入限制：昵称≤20 / 密码6-64；前后端双校。
